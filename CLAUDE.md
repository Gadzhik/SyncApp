# LanSync — заметки для Claude

Обмен файлами и текстом между ПК и телефоном по локальной сети. Топология «ПК как хаб»:
Node-сервер на компьютере раздаёт HTTPS API и мобильную веб-страницу, телефон подключается
по QR-коду. Поставка — один самодостаточный исполняемый файл без Node внутри системы.

Текущая версия — 0.3.0. Всё описанное ниже работает и покрыто тестами (30 шт.).

## Если проект только что перенесён на эту машину

```bash
node --version    # нужен 22 или новее
npm install       # node_modules в репозиторий не входит
npm test          # 30 тестов — быстрая проверка, что перенос удался
```

Ниже Node 22 не заработает: тесты используют `import.meta.dirname` (появился в 21.2), а
упаковка в один файл — `node:sea` с `getRawAsset` (20.12).

Если `npm install` ругается на `sharp` — это нормально и не мешает: он в
`optionalDependencies`, при его отсутствии превью строит отправитель, а `/api/info` отдаёт
`serverThumbs: false`.

Порядок полной проверки изменений описан в скилле `.claude/skills/verify/` — вызывается как
`/verify` или сам подтягивается по запросу «проверь».

## Первое дело: репозиторий ещё не инициализирован

Проект писался без git; 9 августа 2026 года он выложен на GitHub —
<https://github.com/Gadzhik/SyncApp>, ветка `main`, первый коммит «LanSync 0.3.0».
Имя и почта заданы локально для репозитория, глобальный конфиг git на машине пуст.

Что проверять при работе с репозиторием:

1. **`git status` не должен показывать лишнее.** В `.gitignore` уже перечислены `node_modules/`,
   `dist/`, `dist-bin/`, `build/`, `HANDOFF.md`, служебные файлы `.claude/` и записи экрана в
   корне (`/*.mp4`, `/*.mkv`, `/*.mov`, `/*.webm`). GitHub жёстко отклоняет файлы больше 100 МБ,
   а исходная запись интерфейса весит около 160 МБ — в репозитории лежат только сжатые версии
   в `docs/media/`.
2. **Репозиторий публичный.** В коде и документации не должно быть реальных адресов, токенов и
   имён. Примеры обезличены (`192.168.1.42`, `Ab3xK9...`). Если добавляются новые скриншоты или
   записи экрана — проверить, что в кадр не попали QR-код с действующим токеном и адреса
   локальной сети. Токен меняется кнопкой «Отключить все устройства» в интерфейсе.

   Публичность заодно означает, что GitHub Actions бесплатен и без лимита минут — экономить
   на матрице сборки незачем. Оговорка: бесплатны только обычные раннеры. «Larger runners»,
   к которым относятся все нынешние Intel-раннеры macOS, тарифицируются и в публичных
   репозиториях — из-за этого сборки под Intel-маки в матрице нет.

Как выпускается релиз:

```bash
git tag v0.3.0
git push origin v0.3.0
```

По тегу `v*` запускается `.github/workflows/release.yml`: собирает исполняемые файлы на
Windows, macOS (Apple Silicon) и Linux, каждый на своей системе, и публикует их в релиз. После
этого ссылка «страница релизов» в README начинает работать. Версия задаётся в трёх местах —
`package.json`, `VERSION` в `src/server/index.ts` и `version` в ответе `/api/info`
(`src/server/app.ts`); при выпуске держать их согласованными.

На каждый push и pull request работает `.github/workflows/ci.yml`: типы, тесты, синтаксис и
связность клиента на трёх ОС плюс пробная сборка исполняемого файла. Оба workflow начинаются
с `npm ci`, поэтому **`package-lock.json` обязан быть согласован с `package.json`** — после
любых манипуляций с зависимостями проверяй это командой `npm ci` локально, иначе упадут сразу
все сборки.

## Устройство

```

```

## Жёсткие ограничения — не нарушать

1. **Никаких новых нативных зависимостей и внешних исполняемых файлов.** Они ломают сборку
   в один файл. Единственная нативная зависимость `sharp` вынесена в `optionalDependencies`
   и работает по принципу «есть — используем, нет — обходимся». По этой же причине убраны
   `clipboardy` (тащил `xsel`/`clipboard.exe`) и `@fastify/static` (требовал каталог на диске).
2. **Клиент без бандлера.** `src/web` отдаётся как есть. Не добавлять сборку фронтенда —
   на этом держится простота проекта.
3. **Ничего не должно требовать каталога проекта на диске в рантайме.** В собранном виде
   статика лежит внутри бинарника (`node:sea`), см. `src/server/static.ts`.
4. **Список отдаваемых файлов клиента закрытый** (`WEB_FILES` в `static.ts`) — это граница
   безопасности, а не удобство. Добавили файл в `src/web` — добавьте и туда; расхождение
   ловит тест.

## Обмен между компьютерами

Два ПК находят друг друга по mDNS, привязываются по шестизначному коду с экрана принимающего
и шлют файлы напрямую. Что важно помнить:

- **Граница доступа не сдвинута.** Всё управление соседями — только с loopback. Исключение
  одно: `POST /api/peers/adopt` работает без токена, пока на машине показан код привязки, —
  и это единственная такая дверь, кроме `/api/info`.
- **Принимающая сторона ничего нового не разбирает.** Сосед шлёт в обычный `POST /api/files`
  со своим персональным токеном и виден в общем списке устройств. Отвязывается там же.
- **Отправка не через `fetch`.** `undici` буферизует `FormData` целиком; тело собирается
  вручную поверх `node:https` со стримом с диска.
- **Отпечаток сертификата проверяется до создания запроса.** Внутри запроса поздно: событие
  `socket` приходит после рукопожатия, токен успел бы уйти.
- **Тесты обмена ходят по LAN-адресу.** Через 127.0.0.1 авторизация не проверяется вовсе,
  и отзыв доступа выглядит работающим при любом коде.

## Что важно знать перед правками

Полный разбор с деталями — [docs/pitfalls.md](docs/pitfalls.md). Коротко:

- **Тесты поднимают сервер с `tls: false`.** Иначе `fetch` по http не пройдёт.
- **Авторизацию нельзя проверить обычным `fetch`.** Запросы с localhost авторизуются по
  адресу. Нужен `app.server.inject({ remoteAddress: '192.168.1.50' })`.
- **`npm run dev` и бинарник конфликтуют**: один порт 8420 и один каталог `~/LanSync`.
  Перед сборкой убедиться, что запущенный экземпляр остановлен — иначе `EBUSY` при перезаписи
  файла.
- **Занятый порт — не ошибка.** Если на порту отвечает LanSync, приложение открывает браузер
  и выходит с кодом 0. Это осознанное поведение для повторного двойного клика.
- **Правило брандмауэра должно совпадать с категорией сети** (`Get-NetConnectionProfile`).
  Офисный Wi-Fi обычно `Public`, и правило для `Private` молча не работает.

## Проверка изменений

Автотесты не покрывают вёрстку и поведение на реальном телефоне. Порядок:

```bash
npm test && npm run build:binary
npm run dev              # в отдельном окне
npm run smoke            # сквозная проверка: привязка, превью, архив, отзыв устройства
```

`smoke.mjs` ходит по **LAN-адресу**, а не по localhost — только так сервер считает клиента
устройством из сети и включается вся логика токенов.

Для визуальной проверки — открыть `https://localhost:8420` в браузере. Проверять стоит
галочки выбора файлов, превью, панель устройств и блок «Этот компьютер».

## Сознательно не сделано

- **Значок в трее.** Требует нативного кода на каждой ОС — противоречит ограничению №1.
  Его роль играют кнопки на странице («Выключить LanSync», галочка автозапуска) и повторный
  двойной клик по файлу.
- **Докачка после обрыва.** Нужен протокол с чанками и учётом смещения.
- **Кадр из видео для превью.** Потребовал бы ffmpeg.
- **P2P между устройствами.** Осознанно выбран хаб — иначе нужны нативные клиенты.

## Про окружение, где это писалось

Windows 11, Node 24. Рабочий Wi-Fi определяется системой как **Public** — правило
брандмауэра создано для этого профиля. На машине есть виртуальные адаптеры WSL, Hyper-V и
VirtualBox, из-за которых выбор LAN-адреса по эвристике не работал (см. pitfalls).

Оба workflow впервые отработали 9 августа 2026 года и прошли успешно: `ci.yml` целиком,
`release.yml` — на Windows, Linux и macOS ARM. Шаг с `codesign`, которого опасались больше
всего (его нельзя воспроизвести с Windows), работает. Кросс-сборка по-прежнему невозможна
именно из-за него, поэтому каждая платформа собирается на своей.

Тот первый прогон релиза до публикации не дошёл: в матрице стоял раннер `macos-13`, который
GitHub успел вывести из эксплуатации. Задача с несуществующей меткой не падает, а молча висит
в очереди, и задача `release` с её `needs: build` не стартует вовсе. Отсюда правило: если
релиз «не выходит», а сборки зелёные — смотреть, не завис ли кто-то из матрицы в очереди.
Intel-сборка после этого снята совсем.

Собранные файлы доступны двумя путями и путать их не стоит: артефакты прогона появляются
у каждой задачи сразу и живут на странице прогона, а в раздел Releases они попадают только
после того, как отработает **вся** матрица.

Так же не проверялись на реальном устройстве: «Поделиться → LanSync» (только Android) и
установка на домашний экран. Об этом честно сообщать пользователю, а не выдавать за
проверенное.
