# Проверка изменений в LanSync

Порядок важен: каждый следующий шаг опирается на предыдущий. Не пропускать шаги, даже если
правка кажется мелкой — половина ошибок в этом проекте всплывала именно на последнем шаге.

## 1. Типы и тесты

```bash
npx tsc -p tsconfig.json --noEmit
npm test
```

Должно быть 30 проходящих тестов. Если менялся `src/web`, дополнительно:

```bash
node --check src/web/app.js && node --check src/web/api.js && node --check src/web/sw.js
```

И связность разметки — селекторы должны находить элементы, иначе страница молча падает:

```bash
node -e "
const fs=require('fs');
const html=fs.readFileSync('src/web/index.html','utf8');
const js=fs.readFileSync('src/web/app.js','utf8');
const ids=new Set([...html.matchAll(/id=\"([^\"]+)\"/g)].map(m=>m[1]));
const used=[...new Set([...js.matchAll(/\\\$\('#([^']+)'\)/g)].map(m=>m[1]))];
const missing=used.filter(u=>!ids.has(u));
console.log(missing.length? 'ОТСУТСТВУЮТ: '+missing.join(', ') : 'OK: селекторов '+used.length);
"
```

## 2. Сквозная проверка по локальной сети

Освободить порт: `npm run dev` и собранный бинарник используют один порт 8420 и один каталог
`~/LanSync`, вместе они не работают.

```bash
npm run dev      # в фоне
npm run smoke    # когда сервер поднялся
```

`smoke.mjs` ходит по **LAN-адресу**, а не по localhost. Это принципиально: запросы с loopback
авторизуются по адресу, и через localhost логика токенов, привязки и отзыва устройств просто не
включается.

Ожидается 17 PASS. `SKIP` у буфера обмена — норма в сессии без рабочего стола.

## 3. Сборка бинарника

Только если менялся `src/server`, `scripts/build-binary.mjs` или зависимости.

```bash
# остановить запущенные экземпляры, иначе EBUSY при перезаписи файла
npm run build:binary
```

Проверить, что бинарник самодостаточен — скопировать в отдельный каталог **вне проекта** и
запустить оттуда, задав свой порт и каталог данных. Обязательно проверить, что отдаётся
статика (она лежит внутри файла, а не на диске) и что `--stop` останавливает процесс.

## 4. Визуальная проверка

Автотесты не покрывают вёрстку — здесь уже находились ошибки, невидимые для API-тестов
(например, атрибут `hidden`, перебитый авторским `display`). Открыть `https://localhost:8420`
и посмотреть: галочки выбора файлов, превью изображений, панель устройств, блок «Этот
компьютер», мобильный вид на узком экране.

## Чего не проверить локально

- Сборки под macOS и Linux — их делает CI, кросс-сборка невозможна.
- Поведение на реальном телефоне: «Поделиться → LanSync», установку на домашний экран,
  переподключение после блокировки экрана. Об этом честно сообщать пользователю, а не
  выдавать за проверенное.
