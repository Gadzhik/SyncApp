# HTTP API

Базовый адрес — тот же, что у веб-интерфейса: `https://<адрес-ПК>:8420`. Сертификат
самоподписанный, поэтому в `curl` нужен флаг `-k`. При `LANSYNC_TLS=0` сервер работает по
`http://`.

## Авторизация

Все эндпоинты под `/api/` требуют токен, кроме `/api/info`. Токен передаётся одним из
двух способов:

- заголовком `X-Sync-Token: <токен>` — основной путь;
- параметром `?t=<токен>` — для ссылок на скачивание и WebSocket, где заголовок задать нельзя.

Принимаются токены двух видов:

| Вид | Откуда | Отзыв |
|---|---|---|
| Общий | генерируется при первом запуске, лежит в `~/LanSync/config.json`, вшит в QR-код | `POST /api/token/rotate` — отвязывает всё |
| Персональный | выдаётся устройству через `POST /api/pair` в обмен на общий | `DELETE /api/devices/:id` — только это устройство |

Запросы с самого компьютера (`127.0.0.1`, `::1`) проходят без токена: иначе пришлось бы
копировать секрет в собственный браузер. Из этого следует, что эндпоинты с пометкой
«только локально» недоступны с телефона в принципе — проверка идёт по адресу источника,
а не по токену.

Сравнение токенов выполняется `timingSafeEqual`. Ошибки возвращаются как
`{ "error": "текст" }` с соответствующим кодом.

## Сведения о сервере

### `GET /api/info`

Единственный открытый эндпоинт: по нему клиент понимает, что сервер жив, ещё не имея токена.

```json
{
  "deviceName": "my-laptop",
  "version": "0.2.0",
  "local": true,
  "inboxDir": "C:\\Users\\me\\LanSync\\inbox",
  "authorized": true,
  "clipboard": false,
  "keepDays": 7,
  "serverThumbs": false,
  "secure": true
}
```

| Поле | Смысл |
|---|---|
| `local` | запрос пришёл с самого компьютера |
| `inboxDir` | путь к каталогу обмена; наружу не отдаётся (`undefined`) |
| `authorized` | принят ли токен этого запроса |
| `clipboard` | включено ли слежение за буфером обмена ПК |
| `keepDays` | срок автоочистки в днях; `0` — выключена |
| `serverThumbs` | может ли сервер строить превью сам (наличие `sharp`). Превью для присланных файлов строит отправитель, поэтому на отображение это не влияет |
| `secure` | сервер работает по HTTPS |

### `GET /api/connect` — только локально

Данные для подключения телефона: ссылка с токеном и готовый QR-код в SVG.

```json
{
  "url": "https://192.168.1.42:8420/?t=Ab3xK9...",
  "qr": "<svg …>",
  "addresses": ["192.168.1.42", "192.168.56.1"],
  "port": 8420,
  "token": "Ab3xK9...",
  "secure": true
}
```

Отдаётся только на localhost — иначе устройство без токена смогло бы его же и получить.
С телефона отвечает `403`.

### `GET /api/autostart` — только локально

```json
{ "enabled": false, "supported": true }
```

`supported: false` означает запуск из исходников: прописывать автозапуск там бессмысленно,
и интерфейс гасит переключатель вместо молчаливого отказа.

### `POST /api/autostart` — только локально

```json
{ "enabled": true }
```

Включает или отключает запуск вместе с системой.

### `POST /api/shutdown` — только локально

Останавливает приложение. Отвечает `200` и завершается через четверть секунды, чтобы страница
успела получить ответ. `501`, если запущено в режиме без обработчика остановки (например,
внутри тестов).

Нужен потому, что иначе выключить скрыто работающее приложение можно только через диспетчер
задач — недопустимо сложно для обычного пользователя.

### `POST /api/token/rotate` — только локально

Выдаёт новый общий токен, перезаписывает `config.json`, очищает реестр устройств и разрывает
все активные WebSocket-подписки (код закрытия `4001`). Все привязанные устройства мгновенно
теряют доступ и должны отсканировать новый QR-код.

## Устройства

### `POST /api/pair`

Обмен общего токена на персональный. Веб-интерфейс делает это автоматически сразу после
сканирования QR-кода. Имя устройства выводится из `User-Agent`.

```json
{ "device": { "id": "8f1c…", "name": "Android · Chrome" }, "token": "kQ7x…" }
```

Повторный вызов с уже персональным токеном возвращает то же устройство. С самого компьютера
отвечает `400`: привязывать нечего.

### `GET /api/devices`

```json
{
  "devices": [
    {
      "id": "8f1c…",
      "name": "iPhone · Safari",
      "ip": "192.168.1.77",
      "pairedAt": 1754377881234,
      "lastSeen": 1754381401234,
      "online": true
    }
  ],
  "localConnections": 1
}
```

`online` считается по активным WebSocket-подпискам, `lastSeen` обновляется по ответам на ping.
Токены устройств наружу не отдаются никогда. `localConnections` — сколько вкладок открыто на
самом компьютере (они не привязаны к устройству).

### `DELETE /api/devices/:id` — только локально

Отзывает устройство: удаляет запись и разрывает его подписки (код закрытия `4003`). Остальные
устройства и общий токен продолжают работать.

## Файлы

### `GET /api/files`

```json
{
  "files": [
    { "id": "3f2a9c1e5b7d0a84", "name": "отчёт.pdf", "size": 284133, "mtime": 1754377881234, "thumb": false }
  ]
}
```

Список строится сканированием каталога обмена при каждом запросе — отдельного индекса нет,
поэтому файлы, положенные в каталог мимо приложения, тоже видны.

`id` — первые 16 hex-символов SHA-1 от имени файла. Он стабилен между перезапусками, но
**меняется при переименовании** файла. `thumb` показывает, есть ли смысл запрашивать миниатюру.

### `POST /api/files`

`multipart/form-data`, поле `files` (можно несколько). Файлы пишутся на диск потоком.

Необязательное поле `thumb` — готовая JPEG-миниатюра, которую построил сам отправитель.
Учитывается, только если в запросе один файл: в пакетной отправке превью не с чем сопоставить.
Веб-интерфейс всегда шлёт по одному файлу и прикладывает превью для изображений.

```json
{ "saved": [{ "name": "фото.jpg", "size": 2411553 }] }
```

Имена очищаются: берётся только базовое имя, вырезаются управляющие символы и
`< > : " / \ | ? *`, срезаются ведущие точки. Совпадающие имена разводятся суффиксом —
`фото.jpg` → `фото (2).jpg`, поэтому имя в ответе может отличаться от отправленного.

Ограничение — **50 файлов на один запрос**. При превышении возвращается `413` со списком того,
что успело записаться:

```json
{ "error": "принято файлов: 50, остальные отклонены (…)", "saved": [ … ] }
```

Веб-интерфейс с этим ограничением не сталкивается: он отправляет каждый файл отдельным
запросом, по три одновременно.

### `GET /api/files/:id`

Скачивание. Поддерживает `Range` — без этого на телефоне не работала бы перемотка видео.

| Параметр | Действие |
|---|---|
| — | `Content-Disposition: attachment` — скачать |
| `?inline=1` | `Content-Disposition: inline` — открыть в браузере |

Имя отдаётся по RFC 6266 (ASCII-запасной вариант плюс `filename*=UTF-8''…`), поэтому
кириллица и эмодзи в именах не теряются. Ответы `206` при запросе диапазона, `416` при
некорректном.

### `GET /api/files/:id/thumb`

JPEG-миниатюра, вписанная в 256×256, с учётом EXIF-ориентации. Кэшируется в
`~/LanSync/.thumbs`; ключ кэша включает время изменения файла, поэтому подменённый файл
получает новую миниатюру. `404`, если формат не поддерживается, `sharp` недоступен или файл
не удалось разобрать — интерфейс в этом случае показывает значок.

Отдаётся с `Cache-Control: private, max-age=86400, immutable`.

### `DELETE /api/files/:id`

### `POST /api/files/delete`

Пакетное удаление — одним запросом вместо десятка `DELETE`.

```json
{ "ids": ["3f2a9c1e5b7d0a84", "9b1e…"] }
```

```json
{ "removed": ["отчёт.pdf"], "missed": 1 }
```

Файл, который не удалось удалить (занят другим процессом), попадает в `missed`; остальные
удаляются.

### `GET /api/archive`

ZIP-архив, собираемый на лету и сразу уходящий в сокет — временный файл на диске не создаётся.

| Параметр | Действие |
|---|---|
| — | все файлы каталога |
| `?ids=a,b,c` | только указанные |

Сжатие отключено: внутри почти всегда фото и видео, они уже сжаты. При суммарном размере
свыше 4 ГБ автоматически включается ZIP64. `404`, если архивировать нечего.

## Текст и буфер обмена

### `GET /api/clips`

```json
{
  "clips": [
    { "id": "b1e2…", "text": "строка", "from": "телефон", "ts": 1754377881234 }
  ]
}
```

Хранятся последние 50 записей в `~/LanSync/clips.json`, новые первыми.

### `POST /api/clips`

```json
{ "text": "что-нибудь", "from": "телефон" }
```

`text` обязателен и не может быть пустым (`400`). Длиннее 100 000 символов — обрезается.
`from` — произвольная подпись до 40 символов, по умолчанию `устройство`.

### `DELETE /api/clips/:id`

### `POST /api/clips/:id/to-pc-clipboard`

Кладёт запись в буфер обмена компьютера. Если буфер недоступен (например, в SSH-сессии) —
`503`.

## Приём из меню «Поделиться»

### `POST /share`

Цель Web Share Target, объявленная в `manifest.webmanifest`. Запрос перехватывает
service worker: он разбирает `multipart/form-data`, раскладывает файлы в `POST /api/files`,
а текст — в `POST /api/clips`, после чего перенаправляет на `/?shared=1`.

Серверный обработчик существует на случай, когда service worker ещё не активен: он просто
отвечает `303` на `/`, чтобы вместо ошибки пользователь увидел приложение.

Работает только на Android — iOS не поддерживает Web Share Target.

## События

### `WS /api/events`

Токен передаётся в query: `wss://<адрес>:8420/api/events?t=<токен>`.

Сообщения — JSON вида `{ "type": …, "payload": … }`:

| `type` | Когда |
|---|---|
| `hello` | сразу после подключения, `payload.deviceName` |
| `file:added` | загружены файлы, `payload` — массив `{name, size}` |
| `file:removed` | файл удалён; `payload` — `{id, name}`, `{removed: [...]}` или `{cleaned: [...]}` при автоочистке |
| `clip:added` | новая текстовая запись, `payload` — сама запись |
| `clip:removed` | запись удалена, `payload` — `{id}` |
| `devices:changed` | устройство привязано, отвязано, подключилось или отключилось |

Сервер раз в 30 секунд шлёт ping. Если подряд не приходит pong, соединение считается мёртвым
и разрывается — телефон, ушедший из зоны Wi-Fi, не всегда присылает `close`, и без этого
сокет остался бы «наполовину открытым». Браузер отвечает на ping на уровне протокола,
коду страницы делать ничего не нужно.

Коды закрытия: `4001` — сменён общий токен, `4003` — устройство отвязано.

Клиент переподключается сам с экспоненциальной задержкой до 15 секунд и дополнительно
проверяет соединение при возврате вкладки из фона.

## Примеры

```bash
TOKEN=Ab3xK9mQpR7sT2vW5yZ8
HOST=https://192.168.1.42:8420

# -k нужен из-за самоподписанного сертификата
curl -k -H "X-Sync-Token: $TOKEN" $HOST/api/files

curl -k -H "X-Sync-Token: $TOKEN" -F "files=@отчёт.pdf" $HOST/api/files

curl -k -H "X-Sync-Token: $TOKEN" -H "Content-Type: application/json" \
     -d '{"text":"привет","from":"скрипт"}' $HOST/api/clips

# скачать всё одним архивом
curl -k -OJ "$HOST/api/archive?t=$TOKEN"

# получить персональный токен и посмотреть список устройств
curl -k -X POST -H "X-Sync-Token: $TOKEN" $HOST/api/pair
curl -k -H "X-Sync-Token: $TOKEN" $HOST/api/devices
```
